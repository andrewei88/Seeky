# Seeky

A camera-based vocabulary learning app for toddlers. Point the phone at objects, tap them, and the app names what it sees. A real-world picture dictionary that speaks.

The child taps objects through the camera viewfinder. A custom-trained image classifier identifies the object, the app speaks the word aloud with letter-by-letter highlighting, and the child learns to connect real objects with their names. A scavenger hunt mode turns this into a game: "Can you find the... banana?"

## How It Works

The app has two modes:

**Scavenger Hunt (primary).** The app picks 5 objects from its vocabulary and asks the child to find them one at a time ("Can you find the... chair?"). The child points the camera at the matching object and taps it. Correct answers get a celebration; wrong answers get gentle encouragement ("Keep looking!") and another try. If the child doesn't respond, the prompt replays after 8 seconds. Parents can focus on a specific category (animals, fruit, furniture, etc.) or leave it on all for a mixed hunt.

**Explore (secondary).** Free-roaming identification. Tap any object and the app tells you what it is. Explore mode feeds the quiz pool over time as the app learns what's in the child's environment.

Parents access settings via a subtle gear icon (top-right corner). From there: start hunts, switch to explore, pick a focus category, view learning progress, export training captures for model retraining, and manage data. Destructive actions are nested behind a collapsed section and confirmation alerts.

## Architecture

Five layers, top to bottom:

```
Views (SwiftUI)
  -> App (AppState, QuizSession)
    -> Detection (ClassificationEngine, SegmentationEngine, InstanceTracker)
      -> Speech (WordSpeaker)
        -> Data (CorrectionStore, WordProgressStore, TrainingCapture)
```

**Classification pipeline.** When the child taps, the app uses DualCrop classification: an instance-aware crop (sized to the segmented object) and a fixed 270px tap-centered crop are both classified by a custom FastViT-T12 classifier (154 classes, 224x224 input). The instance crop is preferred when it has a clear read (margin >= 3x), since it's segmentation-aware. The fixed crop wins only when the instance is indecisive, which helps isolate small objects sitting on large surfaces. CorrectionStore is checked first: if a parent previously corrected an object, stored embedding similarity takes priority over the model. Default confidence threshold is 0.40, with per-class overrides for tricky objects (cup: 0.30, book: 0.75, mushroom: 0.90).

**Segmentation.** VNGenerateForegroundInstanceMaskRequest runs every 3rd camera frame (~10fps) to track foreground objects. InstanceTracker maintains object identity across frames with a 1.5-second grace period for segmentation dropouts. Tap hit-testing uses padded bounding boxes.

**Audio.** Pre-recorded ElevenLabs audio for all 155 vocabulary words (Jessica voice, 0.7x speed). Phoneme timing data (generated by spectral flux onset detection) drives letter-by-letter highlighting during playback. A render-pipeline lookahead (~28ms) compensates for the delay between reading the audio position and pixels appearing on screen. Celebration clips, encouragement clips, hunt prompts, and category prompts are chained via WordSpeaker's audio queue.

**Learning progression.** WordProgressStore dual-tracks explore mode (feeds quiz pool eligibility) and quiz mode (feeds mastery/spaced repetition). Mastery levels 0-4 based on consecutive correct quiz answers. Spaced repetition intervals increase with mastery. Quiz word selection uses a 4-tier priority system: words due for review, words needing practice, unseen words, then skipped-only words. Skipped words (the child pressed the skip arrow) don't count as wrong answers and rotate back with lower priority.

## The Classifier

Custom FastViT-T12 backbone (Apple, 6.7M parameters). Trained on ~105K images across 154 classes using PyTorch + timm, then converted to CoreML with INT8 quantization (6.5MB deployed weight). The model outputs both softmax probabilities and a 1024-dimensional feature vector (used by CorrectionStore for embedding similarity).

Training uses class-weighted cross-entropy loss with label smoothing (0.1) and a two-phase approach: 5 epochs with frozen backbone, then 25 epochs of full fine-tuning with cosine LR decay.

Current accuracy: 88.9% top-1 validation (154 classes). Model loads in ~4s on device (INT8, down from ~6s with Float16).

### Training Pipeline

```
collect_training_data.py    Aggregate images from multiple sources
curate_training_data.py     Filter duplicates, resize, balance classes
train_classifier.py         Train FastViT-T12 (PyTorch + timm)
convert_to_coreml.py        Export to CoreML (.mlpackage)
verify_classifier.py        Per-class accuracy analysis
```

### Retraining with Phone Captures

Parents can correct misidentified objects using the pencil button. These corrections are stored locally and can be exported as a zip. To retrain:

```bash
python scripts/ingest_phone_captures.py path/to/export.zip
python scripts/train_classifier.py
python scripts/convert_to_coreml.py
```

## Building

Requirements:
- Xcode 16+
- iOS 17+ device (simulator works for logic tests, but camera/Vision features need a real device)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) for project generation

```bash
# Generate Xcode project from project.yml
xcodegen generate

# Build
xcodebuild build -scheme Seeky -destination 'platform=iOS,name=<your device>'

# Run tests (simulator)
xcodebuild test -scheme Seeky \
  -destination 'platform=iOS Simulator,name=Test iPhone' \
  -only-testing:SeekyTests
```

Note: ClassificationIntegrationTests and BundleResourceTests only pass on a physical device. All other tests run on the simulator.

## Vocabulary

155 words across 11 categories: animal, fruit, food, clothing, kitchen item, furniture, body part, vehicle, toy, bathroom item, school supply.

Each word has:
- A pre-recorded `.m4a` audio file (ElevenLabs, Jessica voice)
- A `timing.json` with per-phoneme timestamps for letter highlighting
- Category metadata for quiz filtering

## Key Design Decisions

**Custom model over Apple Vision.** VNClassifyImageRequest is frozen (can't be retrained) and has known confusion pairs (light/moon, laptop/monitor). A custom FastViT-T12 gives us control over the class set, retraining capability, and embedding vectors for correction matching. INT8 quantization keeps the model at 6.5MB.

**DualCrop classification.** A single crop can't serve all cases. Small objects need a tight crop; objects on large surfaces need the segmented instance. DualCrop runs both and picks the winner based on which signal is more confident and more informed (segmentation-aware instance crop vs blind tap-centered crop).

**Freeze frame on tap.** Rendering a pixel-level mask at ~3fps while the camera runs at 30fps looks terrible. Instead, the app captures the camera frame at tap time, displays it as a frozen image on top of the live feed, and renders the mask overlay once on the frozen frame. Same pattern as Google Lens and Apple Visual Look Up.

**No confetti, no gamification.** The app celebrates correct answers with a golden glow, a bouncing word, and a warm voice. No confetti, no stars, no streaks, no characters. Research on the overjustification effect (Lepper, Greene & Nisbett, 1973) shows that external rewards can undermine intrinsic motivation. Seeky's celebration is proportional to the achievement: you found the thing, here's its name, well done. The camera feed is the experience, not a game layer on top of it.

**Corrections over retraining for immediate feedback.** When a parent corrects a misidentification, the correction takes effect instantly via embedding similarity matching (CorrectionStore). Retraining the model is a separate offline process that generalizes across angles and lighting.

**Pre-recorded audio over TTS.** AVSpeechSynthesizer sounds robotic. ElevenLabs voices (recorded once, bundled with the app) sound warm and natural. The tradeoff is ~5MB of audio assets and no dynamic voice generation, but for a fixed 155-word vocabulary this is the right call.

## Known Limitations

- **Laptop/monitor confusion.** The classifier splits ~52/48 when the camera sees a screen with white content, because the distinguishing features (keyboard, hinges) aren't visible when you're looking at just the display.
- **Small objects near large surfaces.** When a small object (fork, plate) sits next to a dominant surface (monitor, countertop), segmentation can group them. The DualCrop logic handles most cases, but edge cases remain.
- **First launch delay.** CoreML compiles the model on first launch (~4s). A "Getting ready..." indicator is shown during this time. Subsequent launches are faster (cached).
- **Two pronunciation issues.** "hand" and "can" have a slightly off vowel sound in the current audio recordings. Queued for re-recording.
