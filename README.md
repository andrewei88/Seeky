# ARYA

A camera-based vocabulary learning app for toddlers. Point the phone at objects, tap them, and the app names what it sees. Think of it as a real-world picture dictionary that speaks.

The core loop: the child taps objects through the camera viewfinder. A custom-trained image classifier identifies the object, the app speaks the word aloud with letter-by-letter highlighting, and the child learns the association between the real object and its name. A scavenger hunt mode turns this into a game: "Can you find the... banana?"

## How It Works

The app has two modes:

**Scavenger Hunt (primary).** The app picks 5 objects from its vocabulary and prompts the child to find them one at a time ("Can you find the... chair?"). The child points the camera at the matching object and taps it. Correct answers get a celebration; wrong answers get gentle encouragement ("Keep looking!") and another try. Parents can filter by location (Home, Zoo, Beach, etc.) and category (animals, fruit, furniture, etc.).

**Explore (secondary).** Free-roaming identification. Tap any object and the app tells you what it is. This is how the app learns what's in the child's environment and builds the quiz pool over time.

Parents access settings via a gear icon: start hunts, switch to explore, pick locations/categories, view learning progress, export training captures for model retraining, and manage data.

## Architecture

Five layers, top to bottom:

```
Views (SwiftUI)
  -> App (AppState, QuizSession)
    -> Detection (ClassificationEngine, SegmentationEngine, InstanceTracker)
      -> Speech (WordSpeaker)
        -> Data (CorrectionStore, WordProgressStore, TrainingCapture)
```

**Classification pipeline.** When the child taps, the app crops a region around the tap point and runs it through a custom FastViT-T12 classifier (149 classes, 224x224 input). CorrectionStore is checked first: if a parent previously corrected an object, stored embedding similarity takes priority over the model. Confidence threshold is 0.40.

**Segmentation.** VNGenerateForegroundInstanceMaskRequest runs every 3rd camera frame (~10fps) to track foreground objects. InstanceTracker maintains object identity across frames with a 1.5-second grace period for segmentation dropouts. Tap hit-testing uses padded bounding boxes.

**Audio.** Pre-recorded ElevenLabs audio for all 155 vocabulary words (Jessica voice, 0.7x speed). Phoneme timing data (generated by spectral flux onset detection) drives letter-by-letter highlighting during playback. A render-pipeline lookahead (~28ms) compensates for the delay between reading the audio position and pixels appearing on screen. Celebration clips, encouragement clips, hunt prompts, and category prompts are chained via WordSpeaker's audio queue.

**Learning progression.** WordProgressStore dual-tracks explore mode (feeds quiz pool eligibility) and quiz mode (feeds mastery/spaced repetition). Mastery levels 0-4 based on consecutive correct quiz answers. Spaced repetition intervals increase with mastery. Words that were only skipped (never answered) don't pollute the review queue.

## The Classifier

Custom FastViT-T12 backbone (Apple, 6.7M parameters). Trained on ~105K images across 149 classes using PyTorch + timm, then converted to CoreML. The model outputs both softmax probabilities and a 1024-dimensional feature vector (used by CorrectionStore for embedding similarity).

Training uses class-weighted cross-entropy loss with label smoothing (0.1) and a two-phase approach: 5 epochs with frozen backbone, then 25 epochs of full fine-tuning with cosine LR decay.

Current accuracy: 90.9% top-1 validation, 97.6% top-5.

### Training Pipeline

```
collect_training_data.py    Aggregate images from multiple sources
curate_training_data.py     Filter duplicates, resize, balance classes
train_classifier.py         Train FastViT-T12 (PyTorch + timm)
convert_to_coreml.py        Export to CoreML (.mlpackage)
verify_classifier.py        Per-class accuracy analysis
```

### Retraining with Phone Captures

Parents can correct misidentified objects using the pencil button. These corrections are stored locally and can be exported as a zip. To retrain:

```bash
python scripts/ingest_phone_captures.py path/to/export.zip
python scripts/train_classifier.py
python scripts/convert_to_coreml.py
```

## Building

Requirements:
- Xcode 16+
- iOS 17+ device (simulator works for logic tests, but camera/Vision features need a real device)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) for project generation

```bash
# Generate Xcode project from project.yml
xcodegen generate

# Build
xcodebuild build -scheme ARYA -destination 'platform=iOS,name=<your device>'

# Run tests (simulator)
xcodebuild test -scheme ARYA \
  -destination 'platform=iOS Simulator,name=Test iPhone' \
  -only-testing:ARYATests
```

Note: ClassificationIntegrationTests and BundleResourceTests only pass on a physical device. All other tests run on the simulator.

## Vocabulary

155 words across 9 locations (Home, Body, Backyard, Neighborhood, Zoo, Aquarium, Farm, Beach, Forest) and 11 categories (animal, fruit, food, clothing, kitchen item, furniture, body part, vehicle, toy, bathroom item, school supply).

Each word has:
- A pre-recorded `.m4a` audio file (ElevenLabs, Jessica voice)
- A `timing.json` with per-phoneme timestamps for letter highlighting
- Location and category metadata for quiz filtering

## Key Design Decisions

**Custom model over Apple Vision.** VNClassifyImageRequest is frozen (can't be retrained) and has known confusion pairs (light/moon, laptop/monitor). A custom FastViT-T12 gives us control over the class set, retraining capability, and embedding vectors for correction matching. The tradeoff is a 12.9MB model that takes longer to load on first launch.

**Freeze frame on tap.** Rendering a pixel-level mask at ~3fps while the camera runs at 30fps looks terrible. Instead, the app captures the camera frame at tap time, displays it as a frozen image on top of the live feed, and renders the mask overlay once on the frozen frame. This is the same pattern Google Lens and Apple Visual Look Up use.

**Spaced repetition for quiz selection.** Words the child answers correctly less often appear more frequently. But skipped words (the child pressed the skip arrow) don't count as wrong answers and don't enter the review queue, because skipping means "not right now," not "I don't know this."

**Corrections over retraining for immediate feedback.** When a parent corrects a misidentification, the correction takes effect instantly via embedding similarity matching (CorrectionStore). Retraining the model is a separate offline process that generalizes across angles and lighting.

**Pre-recorded audio over TTS.** AVSpeechSynthesizer sounds robotic. ElevenLabs voices (recorded once, bundled with the app) sound warm and natural. The tradeoff is ~5MB of audio assets and no dynamic voice generation, but for a fixed 155-word vocabulary this is the right call.

## Known Limitations

- **Laptop/monitor confusion.** The classifier splits ~52/48 when the camera sees a screen with white content, because the distinguishing features (keyboard, hinges) aren't visible when you're looking at just the display.
- **Slow first launch.** CoreML compiles the 12.9MB FastViT model on first run. Subsequent launches are faster (cached).
- **Two pronunciation issues.** "hand" and "can" have a slightly off vowel sound in the current audio recordings. Queued for re-recording.
